# M-Pesa Express Query 

## M-Pesa Express Query Endpoint Details 

- Method: `POST`
- Endpoint:`/mpesa/stkpushquery/v1/query`
- Sandbox URL:`https://sandbox.safaricom.co.ke`
- Description: Queries the status of an initiated M-Pesa Express Payment Request (Prompt) session using its `CheckoutRequestID`. Used to determine whether the customer completed payment, cancelled the prompt, or let the session expire.

## M-Pesa Express Query Sample Request Body

```json
{
  "BusinessShortCode": "174379",
  "Password": "{{password}}",
  "Timestamp": "{{timestamp}}",
  "CheckoutRequestID": "{{checkoutRequestId}}"
}
```
Note: There are no hardcoded values for password, timestamp or checkout requestId in the request body. These values are treated as variables that will be generated by the automation scripts you have set up. 

## M-Pesa Express Query Sample Request Definition


| Name | Description | Type | Required/Optional | Note |
| :---- | :---- | :---- | :---- | :---- |
| BusinessShortCode | The paybill or buygoods account number used to receive mpesa payments. | String | Required | Is between 5 and 7 digits.  Example: 174379 |
| Password | Base64-encoded string used to authenticate the transaction request. | String | Required | **Format:** `Base64(BusinessShortCode + Passkey + Timestamp)` ⚠️ Dynamic value. Must be generated at runtime.  |
| Timestamp | Current time in `YYYYMMDDHHmmss` format in East Africa Time.  | String | Required | ⚠️ Dynamic value. Must be generated at runtime fresh for each request. The timestamp and password are linked and must match. If the `Timestamp` in the payload does not match the timestamp string baked into the `Password` hash, authentication fails immediately with an invalid password error. |
| CheckoutRequestID | A unique tracking identifier generated by Safaricom for an **initiated checkout session** (STK Push prompt).  Serves as the  primary key to poll payment status via `/query` and to match incoming asynchronous callbacks to your database records.  | String | Required | ⚠️ Dynamic stateful value.There is no static mock `CheckoutRequestID` in the sandbox ledger.  To obtain a CheckOutRequestId, You must first call `/processrequest`. Extract the returned `CheckoutRequestID` from the response body and paste it.   |


**Security Warning:** the passkey value provided is the public Safaricom sandbox passkey. Never hardcode live production passkeys in version control or client-side bundles; load them via environment variables (`.env`).

```json
{
   "ResponseCode": "0",
   "ResponseDescription": "The service request has been accepted successfully",
   "MerchantRequestID": "d70d-40dc-a8f8-b6ab4cfc3b0e360414",
   "CheckoutRequestID": "ws_CO_051120262149423708374149",
   "ResultCode": "1037",
   "ResultDesc": "No response from user."
}
```

## M-Pesa Express Query Response Definition



| Name | Description | Type | Note |
| :---- | :---- | :---- | :---- |
| ResponseCode | Indicates the status of the API request.  | string |  `"0"` means the API request lookup succeeded; any non-zero value means the gateway encountered an internal or routing error. |
| ResponseDescription | A human-readable service status message returned by the API gateway | string | Example: T`he service request has been accepted successfully"`. |
| MerchantRequestID | A unique tracking string generated by Safaricom's gateway for the inbound API request. It identifies the merchant's call on Safaricom's web servers and pairs with `CheckoutRequestID` to trace the session in server logs.   | string | none |
| CheckoutRequestID | A unique session tracking identifier generated by Safaricom for the STK Push prompt initiated on the customer's phone. Returned originally by `/processrequest`, it is the required lookup key for the Query API and the primary key used to correlate incoming webhook callbacks with the pending order in your database | string | none |
| ResultCode | Indicates the outcome of the payment transaction | string | 0 is returned for a successful payment. Any other code means that the payment failed. Common failure resultcodes: 1032 is returned if the user cancelled the transaction. |
| ResultDesc | A human readable explanation that describes the final outcome of the payment transaction | string | none  |
